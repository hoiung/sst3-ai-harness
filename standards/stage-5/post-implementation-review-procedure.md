## Procedure

Subagents audit everything the main agent produced. Main agent produced the work; subagents verify it. Stage 5 is a POST-IMPLEMENTATION ADVERSARIAL AUDIT — what did the main agent miss? 100% mandatory — every `/Leader` invocation terminates here. It is DISTINCT from Ralph Review (which ran at Stage 4 and verified delivery). Ralph PASS does NOT mean Stage 5 is satisfied — different lens, different class of findings (TB-3 N36).

**Process**:
0. **Step 0 — scope-snippet re-derive (AC 5.5)**: re-derive every cited line range via `grep -n` at HEAD; record the working-tree SHA (`git rev-parse HEAD`); carry `repo_shape`, `documented_false_positives`, and the Tier-A/B deferred-OK list into the scope file. NEVER inherit line ranges or "file X doesn't exist" claims from a handover or prior-stage artefact unchecked (probe-before-assert, AP #29). Line numbers shift between stages; a stale cited range sends the swarm to the wrong place. **Write-time re-derivation extensions:** verify the diff RANGE file-list separately from any `git log --grep` search, declaring interleaved foreign commits; re-derive count-delta findings from the source table's own column (never subagent arithmetic) plus git-blame (introduced vs pre-existing); re-derive ALL byte-state numbers after a mid-Stage-5 operator decision changes the artifact; baseline the audit SHA only on a settled/idle branch; re-verify surviving findings against HEAD at review-close. **Ralph counter scope (#577):** before any Stage-5 fix or Ralph dispatch, signal Stage-5 entry once with `bash ~/.claude/hooks/sst3-ralph-restart-counter.sh --stage5`, so a scoped Stage-5 Ralph loop starts at restart 0 instead of inheriting Stage 4's terminal state (Stage 4's numbers are archived under the same key; a second call is a no-op).

RESULT block extends with `canonicals_walked` + `section_failures` + `fallback_applied`. Same verify-against-source discipline as the graph-backed audit. See ANTI-PATTERNS.md AP #23. **Twist sub-prompt (#484 V2.4)**: when `invoked_skill ∈ {blog, voice-doc-repo}` AND the delivered diff contains AI-integrated operator-supplied prose, this skill-canonical angle MUST additionally run the STANDARDS.md "Polish vs Twist (Semantic Frame Preservation)" TWIST-forbidden checklist against each delivered polished hunk vs its operator-supplied source (qualifier-add / comparison→verdict / hedge-drop / imposed lens), per-hunk PASS/FAIL — twisting operator-supplied content is an AP #25 regression the heading-walk alone cannot surface; subagent-only, no programmatic detector possible. **Swarm-size heuristic (AC 5.7)**: ≤5 files / ≤50 lines → 3-4 L1 + 1 L2; ≥10 files or a new product module → ≥6 L1. Dispatch as a single parallel batch unless angle B depends on angle A's output. Default tier per STANDARDS.md "Default Tier Assignment per Swarm Role". **Read-only mechanical backstop:** snapshot `git status --porcelain` before/after each read-only leg (a diff flags it); tree-mutating angles (build, fixture create/delete) get their OWN worktree or run serialized, never in the shared read-only pool; the subagent-prompt ban covers rm/mv/redirect-to-repo-path COMPOUND commands, not just `rm -rf`; record/back up untracked scratch files before the swarm; probe-heavy angles write scratch OUTSIDE the audited worktree. **Doc-realignment scoping:** scope each file-audit agent to the WHOLE file, not a section, and run a main-agent cross-file consistency pass against the single dispatch site before applying per-row fixes. Any angle auditing an operator-invoked script RUNS the script's VERBATIM docstring invocation, not only its pytest suite. Those lines, not the exit codes, are the evidence (both exit 0 with drift present). Not `--validate`: on the merged clone nothing is staged, so it checks nothing and exits 0. Surface any consumer drift between merge and Stage 5 in findings.

"The diff adds the row" is a hypothesis until the row is read from the live store. The swarm snippet carries the draft-time-ticked boxes so the audit does not re-tick them from memory.
   - **Sibling-pattern enumeration (AC 5.3)**: for any finding about function X or pattern P, enumerate every sibling file in the same module for the same defect class before returning PASS — use concept-based grep (extract the concept, grep its synonyms), not literal-pattern grep (AP #14e). A parked finding with no assigned angle owner is a dropped finding. <!-- c4:T01 --> The sweep covers every absence or completeness claim, not only function-X findings. <!-- c4:T66 --> A retired-identifier sweep adds a data-flow pass over scripts that replay committed run settings into a live run.

1a. **Chat Reconciliation (Verifier-Led) at Stage 5 — MAIN-AGENT-OWNED, non-delegable (AC 8.1; Stage 5 previously had ZERO chat-history check).** Extract the operator's raw typed messages with `python3 $SST3/extract-chat-agreements.py --issue <N>` and read the research `## Agreements Log`. 2. Layer-2 subtasks in the same Workflow (DIFFERENT angle, per AP#14c): cross-check layer 1. Specifically look for false negatives (problems layer 1 missed). **Raw-tools-only requirement**: at least ONE Layer-2 angle MUST use RAW tools ONLY (direct grep / ast-grep / find / git log) and explicitly prohibit `sst3-*.sh`. The L2 prompt MUST include: "Look OUTSIDE the diff file list — the wrapper-blind class is precisely files NOT in the diff that the change semantically invalidates." The L2 RESULT block MUST carry `wrapper_invoked: no` as the TOP LINE plus one concrete `single highest-impact fix` finding. **REACHABILITY sub-angle:** accept 'no test covers X' / 'X is dead' only with a concrete triggering input; for a deletion claim, grep the test tree for the symbol AND run the affected tests (coverage = documented-retained, not safe-to-strip); for cross-language parity goals, require a NaN/non-finite parity test in BOTH suites; for rules-enforcement code, test 5 paraphrases NOT in current fixtures before sign-off. **Canonical-runner cross-check:** a raw-only agent reporting a TEST FAILURE also runs the project's canonical test command and reports both; a failure only under the non-canonical runner is an environment artifact, not a defect.
3. Main agent reviews ALL RESULT blocks. Verify findings against source. **Verdict-conflict check (AC 5.11)**: any RESULT block with verdict=PASS AND a finding severity > INFORMATIONAL = re-prompt that subagent immediately ("your finding warrants a FAIL — confirm or refute") before accepting the PASS. On a Ralph/Stage-4 conclusion-flip (a verdict reversed after checkboxes closed), re-walk every closed AP #20 checkbox-evidence entry for the SUPERSEDED verdict token before Gate-2 merge. A bug-vs-design verdict requires 3-source intent triangulation (architecture doc, `git log -S` on the primitive, live call-path ownership), any disagreement recorded, never resolved by recency or vibe. When two L1 angles disagree on a binary outcome, re-run the EXACT command both cited and let its output decide, never narrative; for pattern-based scanners, the scope snippet pre-states that detection is pattern-based, not literal-blocklist. <!-- c4:T17 --> When layers disagree whether a defect is live, or an AC names where a check must be green, the smallest real execution at that target decides, output pasted, never source reasoning or a proxy tool.
4. Fix ALL problems. No deferrals. No "low priority". All fixed unless confirmed false positive (document why with evidence). When a finding conflates fixable doc-drift with operator-territory value-tuning, fix ONLY the doc-drift and surface the value question as a JBGE-DEFERRED item with an explicit trigger; never silently absorb the re-tune into scope. Each fix-list entry names its canon anchor (register row, ADR line or canon section) before its mechanism; one with no anchor goes to the operator as a question, not a fix.
5. If fixes were applied: run regression tests AFTER the fixes. This is mandatory — fixing code can introduce new regressions. Verify no regressions before declaring clean. <!-- c4:T76 --> The fixes also get their own read-only review, scoped to the fix diff, before sign-off.
6. If fixes applied: commit, push, update the issue.
7. If no fixes needed: run regression tests anyway to confirm clean state. A Stage-3 'settled / fails-safe' claim never exempts Stage-5 re-testing.
